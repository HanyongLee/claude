# GitHub 버전관리 가이드

이 시스템의 소스는 GitHub 저장소 `HanyongLee/claude` 의 `wholesaler-system/` 아래에서 관리하며, 변경 하나하나가 커밋으로 남습니다. 운영 배포는 **태그(버전 번호)** 단위로 합니다.

## 구조

| 무엇 | 어디 | 역할 |
|---|---|---|
| 개발 브랜치 | `claude/wholesaler-management-system-ae6ph9` | 모든 변경이 커밋·푸시되는 작업 라인 |
| 버전 태그 | `v0.7.0` 형식 | 검증을 통과한 시점의 스냅샷. 태그를 누르면 그 버전의 전체 코드(설치본 포함)를 볼 수 있음 |
| 설치본 | `dist/apps-script/Code.gs` + `appsscript.json` | 각 태그 안에 그 버전의 설치본이 함께 저장됨 |
| 버전 번호 | `gas/Config.gs` 의 `APP.VERSION` | 화면 좌측 상단과 스냅샷에 표시 |

회사 실자료·내부 규정은 저장소에 올리지 않습니다(.gitignore 로 차단, 드라이브에서만 관리). 저장소에는 가상 자료와 익명화된 이름만 있습니다.

## 버전 번호 규칙

`주.부.수` ([유의적 버전](https://semver.org/lang/ko/) 축약)
- **주(0→1)**: 저장 구조가 바뀌어 이관 절차가 필요할 때
- **부(7→8)**: 기능 추가 (예: 독촉 이력, 휴폐업 API)
- **수(0→1)**: 버그 수정만

## 새 버전 내는 절차 (개발 쪽)

1. 변경 후 검증 5개 묶음 실행 — 전부 통과해야 태그를 만든다
   ```
   node tests/run_tests.js && node tests/run_tests_phase2.js && node tests/run_tests_phase3.js \
     && node tests/run_tests_phase4.js && node tests/run_tests_hybrid.js
   ```
2. `gas/Config.gs` 의 `APP.VERSION` 올리기 → 설치본 재생성 `node tools/build_bundle.js`
3. 커밋·푸시 후 태그
   ```
   git tag -a v0.8.0 -m "변경 요약"
   git push origin v0.8.0
   ```

## 운영 중인 Apps Script 를 새 버전으로 바꾸는 두 가지 방법

**방법 A — 설치본 덮어쓰기 (권장, GitHub 접근 불필요)**
1. GitHub 에서 태그 선택 → `wholesaler-system/dist/apps-script/Code.gs` 열기 → 전체 복사
2. Apps Script 편집기에서 Code.gs 전체를 덮어쓰고 저장 (맨 위 폴더 이름 두 줄만 확인)
3. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** (웹앱 주소는 그대로, 자료·설정 유지)

**방법 B — 설치기(update) 사용 (여러 파일 구성으로 설치한 경우)**
1. 특정 버전으로 고정하려면 편집기에서 `setUpdateRef('v0.8.0')` 실행 (브랜치 최신으로 돌아가려면 `setUpdateRef('')`)
2. `update` 실행 → 새 버전 파일을 받아 교체
3. 배포 관리에서 새 버전으로 배포

## 되돌리기 (롤백)

문제가 생기면 **직전 태그의 Code.gs 로 덮어쓰고** 배포 관리에서 새 버전으로 배포하면 끝입니다. 자료는 코드와 분리된 드라이브 시트에 있으므로 코드를 되돌려도 자료는 그대로입니다. 단, 주 버전이 올라간 뒤의 롤백은 저장 구조 안내를 먼저 확인하세요.

배포 자체의 이력은 Apps Script **배포 관리** 화면에 버전 번호로 남고, 이전 배포 버전을 선택해 즉시 되돌릴 수도 있습니다.
