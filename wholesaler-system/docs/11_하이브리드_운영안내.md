## 1. 담당자 드라이브 폴더를 그대로 쓰는 방법

```
2611_AI혁신센터_채권관리/            ← 담당자 드라이브의 기존 폴더 (루트)
├─ (기존) 낙찰 실적·사업실적·담보현황 .xlsx   ← 정기 처리가 자동으로 읽고 '02_가져오기_완료'로 옮김
├─ 01_가져오기_대기/   새 추출 파일·동향보고 파일을 넣는 곳 (루트에 바로 넣어도 됨)
├─ 02_가져오기_완료/   처리된 원본 보관
├─ 03_가져오기_오류/   읽지 못한 파일
├─ 10_원본서식/  20_관리건/  30_증빙/
├─ 40_배포/            매일 생성되는 스냅샷 HTML (전체용 1개 + 경매사별)
├─ 90_백업/
└─ 중도매인 통합관리_DB_*.gsheet 6개   ← 저장소 시트 (직접 편집 금지)
```

설치 후 편집기에서 **`setupWithFolder('2611_AI혁신센터_채권관리')`** 를 실행하면 위 구조가 그 폴더 안에 만들어집니다. 그다음 `runPipeline`(또는 `setupAllWithoutVirtualData`) 을 실행하면 폴더에 있던 엑셀 파일이 자동으로 적재됩니다.

**계정 주의**: Apps Script 프로젝트는 **그 폴더를 소유한 Google 계정**(폴더를 만든 담당자 계정)으로 만들어야 합니다. 다른 계정으로 만들면 폴더가 공유돼 있어도 저장소 시트를 그 계정이 소유하게 되어 "담당자 1명의 드라이브로 관리"라는 목표에 어긋납니다.

## 2. 폴더에 있는 농협 추출 파일을 어떻게 읽는가

파일명이 아니라 **헤더 행**으로 형식을 판별하므로 파일명은 자유입니다. 엑셀은 Drive API 로 잠시 Google 시트로 변환해 읽고 임시 파일은 휴지통으로 보냅니다(매니페스트에 고급 Drive 서비스 포함).

| 파일 | 판별 헤더 | 적재 결과 | 시스템에서 쓰이는 곳 |
|---|---|---|---|
| 중도매인 낙찰 실적 기초자료 (EBFW916007 **일별**) | 번호,조직구분,사업장,사업장명,**기표일자**,농협대분류… | `R_SALES` 1행 = (기표일자, 중도매인, 분류 조합). 대분류 과일·채소는 그대로, 곡류·특작·절화·관엽·분화는 **기타**. 거래구분은 **미구분** | 구매 실적, 전년 비교, 구매 급감 신호(S04), 매트릭스 가로축 |
| 공판장거래인 사업실적 (EBFW916007 **월별**) | …,**기표년월**,중도매인,중도매인명,중량,금액(A) | `R_SALES_MONTHLY` 1행 = (중도매인, 월). **일별 자료가 없는 달에만** 월 집계로 사용(구매일수·부류 구성비 없음). 맨 아래 합계 행은 건너뜀 | 24개월 추이, 전년 동기 누적, 이 파일만 있을 때의 전년 동월 비교·S04·증감 순위(2-1) |
| ★중도매인 담보현황 (기준일) | ,허가 번호,성명,품목,갱신 년도,… | 중도매인 기본정보(허가번호=코드, 성명, 품목, 허가일), 한도 3종(외상한도→**기본한도**, 마감한도, 추가한도 — 합산 안 함), 담보 종류별 설정금액(거래보증금·부동산·보증보험·예금·보험), 보증보험 만기일, 연대보증 유무·보증인(별도 개인정보 저장소) | 통합 상세, 기한 도래 신호(S06), 한도 사용률(결합 방식 확정 후) |
| 계통마트 실적 기초자료 (EBFW916004) | 번호,유통거래처지역본부,… | **적재하지 않음**(참고자료로 기록만). 하나로마트 공급 실적은 채권 지표와 무관 | — |

적재 규칙
- 담보현황은 **값이 바뀐 항목만 새 승인 버전**을 만들고 이전 버전은 기준일 전날로 종료합니다(기준일은 파일명의 `26.9.16.기준`에서 읽음). 같은 파일을 다시 넣어도 중복 버전이 생기지 않습니다.
- 담보의 **평가금액·내부 인정금액은 비워 둡니다**("파일 적재(내부 인정금액 미확인)"). 설정금액을 회수 가능액으로 보지 않는다는 원칙 그대로입니다.
- **NICE 신용점수 열은 읽지 않습니다**(개인신용정보).
- 실적 파일에만 있는 중도매인은 자동 등록됩니다(설정 `NH_AUTO_REGISTER_WS`, 거래 시작일 = 파일 내 최초 거래일, 비고에 "자동 등록" 표시).
- 같은 날·같은 분류 조합의 금액이 이전 적재와 다르면 **거부**합니다(원천 정정은 담당자 확인 후 처리).

### 2-1. 월별 사업실적 파일만 있을 때
월별 사업실적 파일 하나만 폴더에 있어도 정기 처리가 스냅샷까지 끝까지 돕니다(일별 낙찰·미수 자료 없음). 담당자 폴더의 실제 파일로 적재·대사까지 확인했습니다(수치는 저장소에 적지 않음).

| 항목 | 동작 |
|---|---|
| 기준일 | 일별·미수 자료가 없으면 **최신 기표년월의 말일**. 자료 시작일은 첫 달 1일 |
| 전년 동월 비교 | 마감 월 합계 ÷ 전년 같은 달 합계 (방법 "월 합계(월별 사업실적)") |
| 직전 3개월 비교 | 마감 월 합계 ÷ 직전 3개월 월평균 (경매일 환산 없음) |
| 시장 대비 | 중도매인 증감률 − 전체 중도매인 합계 증감률 |
| S04 구매 급감 | 위 세 조건(기본 −40% · −30% · −20%p, 모두 [가정])을 **모두** 충족할 때만 신호. 전년 대비만 크게 줄어든 중도매인은 아래 증감 순위에서 확인 |
| 4분면 | 회전율을 셀 수 없으므로 **전년 동월 대비 증감률 가로 막대**(감소 상위 15명 + 증가 상위 5명)로 대체. 전년 동월엔 거래가 있었으나 마감 월 거래가 없는 중도매인은 −100%로 섞지 않고 접힘 목록으로 따로 셈. 미수 자료가 들어오면 자동으로 4분면으로 바뀜 |
| 스냅샷 | 정기 처리에서 스냅샷 생성이 실패해도 처리 자체는 완료되고 작업 이력에 실패가 남음 |

파일의 `중도매인` 열(번호)이 중도매인 코드가 되고 `중도매인명`은 상호(성명)로 등록됩니다. 담보현황 파일의 허가번호와 같은 체계인지 담당자가 한 번 확인해 주세요 [확인 필요].

### 이 파일들로 할 수 없는 것 (솔직한 범위)
입금·미수잔액·연체 자료가 없으므로 **회전율·회수일수·연체·미수금 증가·한도 사용률과 그 신호(S01·S02·S03·S05)는 "산출불가"로 표시**됩니다. 화면과 스냅샷 상단에 "미수·입금 자료 없음" 배지가 뜹니다. 정산·채권 시스템에서 **중도매인별 일자별 미수잔액(연체금액·연체일수 포함)** 과 **입금 내역**을 추출할 수 있으면 `AR_BAL_`·`RECEIPT_` 형식(1단계 안내 3장)으로 넣거나, 그 추출 화면의 열 구조를 알려주시면 어댑터를 추가하겠습니다. 그때부터 설계의 회수 지표 전체가 동작합니다.

## 3. 스냅샷 HTML (사내망 배포)

- 정기 처리(06시) 마지막 단계에서 `40_배포` 폴더에 **`중도매인관리_YYYYMMDD_전체.html`** 과 **경매사별 파일**을 만듭니다(설정 `SNAPSHOT_ENABLED`). 같은 날 다시 만들면 덮어씁니다.
- 한 파일에 화면·스크립트·자료가 모두 들어 있어 **사내망 PC에서 그냥 열면** 됩니다(로그인·설치·Google 접속 없음).
- 내용: 오늘 처리할 일 · 신호와 근거 수치 · 중도매인별 실적·한도·담보·보증 · 매트릭스 · 관리 건(신호·동향보고·조치) · 상황별 절차·근거 안내 · **동향보고 작성 폼**.
- 제외: 보증인 성명·연락처·증빙·변경 이력. 경매사 파일에는 **담당 중도매인만** 들어갑니다.
- 전달: 관리자가 `40_배포` 에서 내려받아 사내 메일·게시판에 올립니다. 설정 `SNAPSHOT_EMAIL=예` 로 바꾸면 경매사 이메일로 첨부 발송합니다(금액이 포함된 파일이므로 조직 기준 확인 후).
- 샘플(가상 자료): `docs/샘플_스냅샷_전체.html`, `docs/샘플_스냅샷_경매사A.html` — 브라우저로 열어 보세요.

## 4. 동향보고 파일 제출 (로그인 없는 입력)

1. 경매사가 스냅샷의 **"동향보고 작성"** 에서 관리 건을 고르고 확인일·확인 방법·확인된 사실·결과 분류·재점검일을 입력 → **파일 만들기** → `TREND_<관리건ID>_<확인일>.json` 다운로드.
2. 사내 메일로 채권담당에게 보냅니다.
3. 채권담당이 파일을 드라이브 폴더(루트 또는 `01_가져오기_대기`)에 넣습니다.
4. 다음 정기 처리가 **작성자가 그 관리 건의 담당 경매사인지** 확인한 뒤 보고서로 적재합니다(공식 원본 = 파일 제출, 파일은 잠긴 첨부로 보관). 결과가 "채권 검토 필요"면 관리 건이 조치 단계로 넘어갑니다.
5. 담당이 아닌 사람의 파일, 형식 오류 파일은 `03_가져오기_오류` 로 가고 가져오기 화면에 사유가 표시됩니다. 같은 파일을 두 번 넣어도 중복 적재되지 않습니다.

## 6. 알려진 한계

1. **실제 엑셀 파일로는 아직 돌려보지 못했습니다.** 열 이름이 추출 화면 버전에 따라 조금 다를 수 있습니다. 처음 `runPipeline` 후 가져오기 화면에서 배치 상태가 "형식오류"면 거부 메시지(찾지 못한 열 이름)를 알려주세요.
2. 엑셀 변환은 Drive API 호출 1회·임시 시트 생성 1회가 파일마다 듭니다. 파일이 수십 개면 실행시간 분할이 작동하지만 느립니다. CSV 로 저장해 올리면 변환 없이 바로 읽습니다.
3. 월별 사업실적만 있는 달은 구매일수·부류 구성비가 없습니다. 그 달의 "동일 경과 경매일" 비교도 불가합니다.
4. 담보현황의 "담보만기일(담보종류)" 열은 자유 서식이라 첫 날짜만 읽습니다. 여러 담보의 만기가 섞여 있으면 보증보험·예금에 같은 날짜가 들어갈 수 있으니 통합 상세에서 확인하세요.
5. 스냅샷은 **하루 1회**이고 파일을 받은 사람은 파일 안 자료를 모두 볼 수 있습니다. 외부 전달 금지 안내가 파일 상단에 있습니다.
6. 폴더 소유 계정과 Apps Script 계정이 다르면 저장소 시트의 소유가 갈립니다(1장 계정 주의).

## 7. 업무매뉴얼(HWP) 등록 — 담당자 드라이브의 매뉴얼 폴더

매뉴얼 폴더(예: `기초 자료`)에 있는 HWP 파일들을 한 줄로 등록합니다. 저장소 문서에는 실제 규정명을 적지 않습니다.

```
registerManuals('기초 자료')        ← 편집기에서, 또는 웹앱 "매뉴얼·서식 → 매뉴얼 폴더 한 번에 등록"
```

| 하는 일 | 설명 |
|---|---|
| 문서·버전 등록 | 파일마다 문서 1건·버전 1건. 파일명의 `(yyyy.mm.dd 개정)` 이 시행일·버전. 개정일이 없는 파일은 **"시행일 미확인"** 으로 등록되니 확인 후 수정 |
| 상황 코드 9개 생성 | 연체 발생·30일·90일, 회전율 저하, 미수금 증가, 구매 급감, 한도 상승, 담보·보증 기한, 복수 징후 |
| 근거 후보 연결 | 편·장 제목의 키워드(임의회수·집행보전·담보취득·감정평가·여신관리·부실위험조사 등)로 상황별 **근거 후보 문서**를 연결. 화면에서 파일 링크로 바로 열림 |

**담당자가 할 일**: 상황별 근거 후보 문서를 열어 해당 조항을 확인하고, "절차 단계 등록"에 단계·내용·조항·쪽수·필요 서식을 입력합니다. 입력된 순간부터 절차 안내·매뉴얼 질의·근거 스냅샷에 그 조항이 인용됩니다. 첫 대상으로는 **연체 발생(SIT-OVD-NEW)** 과 **담보·보증 기한 도래(SIT-COLL-EXPIRY)** 를 권합니다.

폴더 위치: 매뉴얼 폴더가 `2611_AI혁신센터_채권관리` 밖에 있어도 파일 ID로 참조하므로 동작합니다. 담당자 폴더 하나로 관리하려면 안으로 옮기는 것을 권합니다(옮겨도 ID 가 유지되어 재등록이 필요 없습니다).

### 이상징후 체크리스트 (현장 확인) — 핵심 10개
금융회사의 여신 사후관리·조기경보(EWS) 항목과 농산물 유통업 부실 징후 자료를 조사해, **공판장 중도매인에게서 현장 직원이 눈으로 확인할 수 있는 것** 10개로 줄였다. 목적은 연체채권 발생 가능성을 **미리** 알아채는 것이다. 모든 항목은 **[가정]** 이며 `M_CHECKLIST` 시트에서 담당자가 문구·가중치를 고친다.

| No | 구분 | 확인 항목 | 가중치 | 왜 넣었나 |
|---|---|---|---|---|
| 1 | 인력 | 종업원·배송 인력이 줄었거나 경리·판매 담당 등 핵심 직원이 그만뒀다 | 2 | 인건비를 먼저 줄이는 것은 매출·수익 감소의 강한 신호. 현장에서 바로 보인다 |
| 2 | 결제 | 결제일 연기·분할·부분 결제 요청, 결제 약속 불이행 | 2 | 금융권 연체 조기경보의 1순위 항목 |
| 3 | 결제 | 결제 수단 변경(현금→어음·카드·소액 분할, 제3자 명의 입금) | 1 | 자금 사정 악화 시 결제 패턴이 먼저 바뀐다 |
| 4 | 거래 | 경매 참여 횟수 감소, 낙찰 물량·단가 급감·저가 위주 | 1 | 영업 축소의 직접 지표. 실적 자료로도 보조 확인 |
| 5 | 거래 | 주요 납품처(마트·식당·소매) 이탈·축소, "거래처에서 돈을 못 받는다" 호소 | 1 | 연쇄 미수의 전조 |
| 6 | 현장 | 점포·창고 재고 비정상 감소, 차량·설비 축소·매각, 운영 시간 단축 | 1 | 자산 처분·운영 축소 |
| 7 | 대표자 | 대표자 연락 회피·현장 부재, 건강·가정·소송·경영권 분쟁 | 2 | 소규모 사업체는 대표자 사정이 곧 상환 능력 |
| 8 | 신용 | 타 금융기관 연체, 세금 체납, 압류·가압류 통지, 담보 부동산 처분·추가 설정 | 2 | 금융권 공통 부실 징후. 담보 가치 훼손과 직결 |
| 9 | 자금 | 선지급·외상한도 증액·결제 유예의 급한 요청, 사채·고금리 자금 정황 | 2 | 유동성 위기 신호 |
| 10 | 관계 | 다른 공판장·도매시장으로 거래 이전, 다른 중도매인 명의 거래 | 1 | 거래 이탈·명의 대여는 회수 경로 상실 |

- 가중치 합 **4 이상(가정, `CHECKLIST_HIGH_SCORE`)** 이면 "연체 가능성 높음"을 제안만 한다. 예: 인력 감소(2) + 결제 연기(2).
- 참고 자료: 미국 농산물 유통업계 신용정보기관 Blue Book 「Detecting Distressed Businesses」(거래처 부실 징후), 국내 기업 부실 징후 체크리스트(삼성경제연구소, 1998 보도), 금융회사 여신 사후관리·조기경보 일반 항목. 공판장 특성에 맞게 재구성했으며 어느 기관의 공식 기준도 아니다.
- 흐름: 스냅샷·웹의 **인쇄용 서면** → 경매사가 대면·경매 현장에서 체크 → 담당자가 웹앱 "체크리스트 입력"에서 결과 입력 → 동향보고(확인 방법 "현장 체크리스트(서면)")로 기록 → 관리 건 흐름. "예"만 확인된 사실로, "미확인"은 추가 확인사항으로 남는다.
- 서면 스캔은 파일명 `CHECK_<관리건ID>_<날짜>.pdf|jpg|png` 로 폴더에 넣으면 관리 건 증빙(잠금)으로 첨부된다.

### 4분면 — 원 하나 = 중도매인 한 명, 클릭하면 전년 동월 위치(점선)
- 원 하나가 중도매인 한 명. 세로 = 최근 3개월 미수금 회전율, 가로 = 마감 월 사업실적의 전년 동월 대비 증감률, 크기 = 당월 실적.
- **원을 누르면** 같은 색의 **점선 원**이 전년 동월 위치(당시 증감률·당시 회전율·당시 실적)에 나타나고 실선으로 이어진다. 다시 누르면 사라진다. 전년 위치는 **전전년 동월** 자료까지 있어야 계산되므로, 자료가 24개월 미만이면 "전년 위치 없음"으로 안내만 한다.
- 미수잔액·입금 자료가 없는 동안은 회전율을 셀 수 없어 점이 표시되지 않는다(스냅샷 상단에 안내). 자료가 들어오면 자동으로 채워진다.

### 주기·배포 (기본 월요일)
- 설정 `SNAPSHOT_FREQ=주간`, `SNAPSHOT_WEEKDAY=1`(월요일). 월요일 06시 정기 처리에서 `40_배포`에 생성한다. 수동(`buildSnapshotsNow`)은 언제든 생성.
- 스냅샷은 **자바스크립트·CSS가 들어 있는 단일 HTML 파일**(반응형, 휴대폰 폭 대응, 외부 접속 없음)이다. 사내 이메일에 파일로 첨부하거나 임직원 단톡방에 올리면 된다.
- 카카오톡 주의: 단톡방에서 파일을 바로 누르면 앱 안 미리보기가 스크립트를 막아 탭·4분면 클릭이 동작하지 않을 수 있다. **"다른 앱으로 열기 → 브라우저(크롬·삼성인터넷)"** 또는 PC에서 내려받아 열도록 안내문을 함께 올린다. 메일 첨부는 PC 브라우저에서 바로 열린다.
- 보증인 성명·연락처 등 PII는 스냅샷에 들어가지 않지만 중도매인별 실적·미수는 들어가므로 외부 전달 금지 문구가 파일 상단에 있다.
